📋 Hermes Agent Kanban 看板系统

Kanban 是一个多智能体协作看板，支持任务依赖管理、并行 worker 调度、自动重试与熔断恢复。通过 Dashboard 实时观察系统运行状态，worker 通过专用工具集驱动看板运转。

kanban_* 工具集
Worker 通过这 9 个专用工具驱动看板，无需访问 Dashboard 或 CLI
工具名称功能描述典型调用场景
kanban_show显示任务详情（含父任务交接数据）Worker 启动时首先调用
kanban_list列出任务（支持过滤）查看当前队列状态
kanban_create创建新任务Pipeline 中上游任务创建下游
kanban_complete完成任务（写入 summary + metadata）Worker 完成工作时调用
kanban_block阻塞任务（需人工介入）Review 不通过 / 缺少凭证
kanban_unblock解除阻塞人工解决问题后
kanban_heartbeat发送心跳（汇报进度）长时间任务的中间状态更新
kanban_comment添加评论记录上下文信息
kanban_link链接任务（建立依赖关系）构建任务 DAG

故事 1：独立开发者交付功能
经典流程 — 设计 Schema → 实现 API → 编写测试，三任务父子依赖自动推进
Design auth schema
@backend-dev
→
Implement auth API
@backend-dev
→
Write tests
@qa-dev
bash创建依赖任务链
# 创建父任务 → 自动获得 ready 状态
SCHEMA=$(hermes kanban create "Design auth schema" \
    --assignee backend-dev --tenant auth-project --priority 2 \
    --body "Design user/session/token schema." --json | jq -r .id)

# 创建子任务 → 等待父任务完成（停留在 todo）
API=$(hermes kanban create "Implement auth API endpoints" \
    --assignee backend-dev --tenant auth-project --priority 2 \
    --parent $SCHEMA \
    --body "POST /register, POST /login, POST /refresh" --json | jq -r .id)

# 创建孙任务 → 等待 API 任务完成
hermes kanban create "Write auth integration tests" \
    --assignee qa-dev --tenant auth-project --priority 2 \
    --parent $API
✅ 依赖推进引擎：当父任务完成（Done），依赖引擎自动将子任务从 todo 提升到 ready。下游 Worker 通过 kanban_show() 自动看到父任务的 summary + metadata（结构化交接）。

故事 2：舰队式批量处理（Fleet Farming）
三个 Worker 并行拉取独立任务，实时显示进度 —— 适合批量内容处理、数据转录等场景
bash启动舰队 + 批量创建任务
# 启动 Gateway（嵌入式 dispatcher 会拾取所有 profile 的任务）
hermes gateway start

# 批量创建翻译任务（translator worker 会并行处理）
for lang in Spanish French German; do
    hermes kanban create "Translate homepage to $lang" \
        --assignee translator --tenant content-ops
done

# 批量创建转录任务
for i in 1 2 3 4 5; do
    hermes kanban create "Transcribe Q3 customer call #$i" \

故事 3：角色管道与重试（Role Pipeline with Retry）
PM 写规格 → 工程师实现 → Review 拒绝 → 工程师重试 → Review 通过。展示 Kanban 如何处理多轮迭代。
Spec: password reset
PM ✅
→
Implement password reset
Engineer ✅ 第2次尝试
→
Review PR
Reviewer ✅

运行历史（Run History）— 同一任务多次尝试：

BLOCKED
Run 1 · @backend-dev ·
原因：password strength check missing，reset link isn't single-use
COMPLETED
Run 2 · @backend-dev ·
修复：added zxcvbn check，reset tokens now single-use
💡 重试历史是主要表示：第二次 Worker 启动时，kanban_show() 返回的 worker_context 包含第一次被阻塞的原因，因此第二次 Worker 精确知道要修复什么问题，而不是重新阅读整个规格。

故事 4：熔断器与崩溃恢复
Real workers fail. 看板提供双重防线：熔断器（连续失败自动阻塞）+ 崩溃检测（PID 消失后自动回收任务）
⚡

熔断器 Circuit Breaker

连续 N 次 spawn 失败后自动将任务设为 Blocked（gave_up），不再重试直到人工 unblock。

TRY 1
spawn_failed
→
TRY 2
spawn_failed
→
GAVE UP
→ Blocked
🔄

崩溃恢复 Crash Recovery

Dispatcher 通过 kill(pid, 0) 检测 Worker 进程是否存活，死亡后自动释放 claim 并重新调度。

CRASHED
Run 1 · OOM kill at row 2.3M
COMPLETED
Run 2 · chunked strategy with LIMIT

结构化交接 — Summary & Metadata
kanban_complete(summary=..., metadata=...) 是工作流阶段之间交接的主要通道，而非装饰。
pythonWorker 完成任务时调用
kanban_complete(
    summary="added zxcvbn strength check, "
              "reset tokens are now single-use",
    metadata={
        "changed_files": ["auth/reset.py", "auth/tests/test_reset.py"],
        "tests_run": 11,
        "review_iteration": 2,
    },
)
Worker Context 内容作用
prior attempts（outcome / summary / error / metadata）重试 Worker 不会重复失败路径
Parent task results（最新 completed run 的 summary + metadata）下游 Worker 看到上游工作的原因和方式
⚠️ 批量关闭保护：CLI 不支持向多个任务复制相同 summary（会被拒绝）。工具表面完全不暴露 bulk variant —— kanban_complete 始终一次只处理一个任务。

常用命令速查
快速参考 — 初始化、任务管理、运行历史、事件监控
bash初始化与 Dashboard
hermes kanban init           # 初始化看板（首次运行自动初始化）
hermes dashboard             # 打开 Dashboard → http://127.0.0.1:9119
hermes gateway start         # 启动 Gateway（嵌入式 dispatcher）
bash任务管理
hermes kanban create "Task name" --assignee <profile> --tenant <tenant>
hermes kanban show <id>      # 查看任务详情
hermes kanban runs <id>      # 查看运行历史
hermes kanban list            # 列出所有任务
hermes kanban specify <id>   # AI 完善一句话需求为完整规格
hermes kanban unblock <id>   # 解除阻塞
bash事件监控
hermes kanban watch --kinds completed,gave_up,timed_out
# 实时流式传输整个看板的事件

hermes kanban notify-subscribe <task> --platform telegram --chat-id <id>
# 在特定任务完成时获取 gateway ping
📁 数据存储：默认看板 ~/.hermes/kanban.db；自定义看板 ~/.hermes/kanban/boards/<slug>/kanban.db。三个界面（Dashboard、CLI、Worker 工具）都通过同一个 per-board SQLite 数据库路由。
