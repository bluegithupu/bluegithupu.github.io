📋 概述

大规模功能需要仔细规划和系统执行，以避免压倒性的复杂性。本指南概述了一个经过验证的工作流程，用于将大规模项目分解为可管理的阶段，使用规范模式进行规划，并通过频繁验证进行迭代实现。

Version Control Strategy

🔄 工作流程步骤

创建总体计划

使用规范模式创建全面文档，将项目分解为主要阶段。

分阶段实现

为每个阶段开始新会话，参考总体计划文档。

频繁提交和PR

创建与每个已完成阶段相对应的git提交和拉取请求。

增量验证

在每个阶段后测试并验证功能，而不是在最后。

更新计划

标记已完成的阶段，并根据学习情况调整剩余工作。

📝 阶段1：使用规范模式进行总体规划

创建详细实施计划

首先使用 Shift+Tab 进入规范模式并创建全面分解：

EN - 原版提示词
Create a detailed implementation plan for migrating our entire authentication system from Firebase Auth to Auth0. This affects user login, registration, session management, role-based access control, and integrations across 50+ components. Break this into major phases that can be implemented independently with clear testing and validation points. Each phase should be completable in 1-2 days and have minimal dependencies on other phases.
中文 - 中文提示词
为将我们的整个认证系统从 Firebase Auth 迁移到 Auth0 创建详细的实施计划。 这涉及用户登录、注册、会话管理、基于角色的访问控制以及跨 50+ 组件的集成。 将其分解为可以独立实现的主要阶段，并具有清晰的测试和验证点。 每个阶段应在 1-2 天内完成，并且对其他阶段的依赖最小。

规范模式将生成

阶段分解 (Phase Breakdown) - 4-6个主要实现阶段
依赖关系映射 (Dependency Mapping) - 哪些阶段必须在其他阶段之前完成
测试策略 (Testing Strategy) - 如何验证每个阶段的正确性
风险评估 (Risk Assessment) - 潜在问题及缓解策略
回滚计划 (Rollback Plan) - 如何在需要时安全恢复
💾 保存计划 - 批准规范并将保存为项目根目录中的 IMPLEMENTATION_PLAN.md。

🔨 阶段2：迭代实现

对于计划中的每个阶段

开始新的会话

为每个阶段开始新的droid会话以保持专注和清晰的上下文。

参考总体计划

阶段1的示例提示：

EN - 原版提示词
I'm implementing Phase 1 of the authentication migration plan documented in IMPLEMENTATION_PLAN.md. Phase 1 focuses on setting up Auth0 configuration and creating the basic authentication service without affecting existing Firebase integration. Please read the plan document and implement this phase, then update the document to mark Phase 1 as complete.
中文 - 中文提示词
我正在实施 IMPLEMENTATION_PLAN.md 中记录的认证迁移计划的第1阶段。 第1阶段专注于设置 Auth0 配置并创建基本的认证服务， 而不影响现有的 Firebase 集成。 请阅读计划文档并实施此阶段，然后更新文档以将第1阶段标记为完成。

对复杂阶段使用规范模式

对于涉及重大变化的阶段，使用 Shift+Tab 获得详细规划：

EN - 原版提示词
Following IMPLEMENTATION_PLAN.md, implement Phase 3: Update all login components to use the new Auth0 service while maintaining backward compatibility with the existing Firebase auth as fallback.
中文 - 中文提示词
按照 IMPLEMENTATION_PLAN.md，实施第3阶段： 更新所有登录组件以使用新的 Auth0 服务， 同时保持与现有 Firebase 认证的后向兼容性作为后备。

频繁提交

每个阶段完成后，要求Droid提交更改：

EN - 原版提示词
Commit all changes for Phase 1 of the auth migration with a detailed message.
中文 - 中文提示词
提交认证迁移第1阶段的所有更改，并附上详细的提交信息。
EN - 原版提示词

中文 - 中文提示词

Droid将暂存所有更改并创建具有适当共同作者归属的提交。

创建特定阶段的PR

要求Droid为每个完成的阶段创建拉取请求：

EN - 原版提示词
Create a PR for the auth migration Phase 1 work on a new branch called auth-migration-phase-1.
中文 - 中文提示词
在一个名为 auth-migration-phase-1 的新分支上，为认证迁移第1阶段的工作创建一个 PR。
EN - 原版提示词
Open a pull request with a comprehensive description of what was completed and testing done.
中文 - 中文提示词
打开一个拉取请求，并附上已完成工作和测试的全面描述。

Droid将创建分支，推送更改，并根据所做的提交和更改生成详细的PR描述。

🧪 阶段3：验证和测试策略

独立测试每个阶段

不要等到最后 - 在每个阶段后验证功能：

阶段1完成

EN - 原版提示词
Run the authentication tests and verify the Auth0 service works in isolation. Test user registration, login, and logout with the new service.
中文 - 中文提示词
运行认证测试并验证 Auth0 服务在隔离环境下正常工作。 使用新服务测试用户注册、登录和注销。

阶段2完成

EN - 原版提示词
Test the migration script with a subset of test users. Verify data integrity and that users can log in with both old and new systems.
中文 - 中文提示词
使用一部分测试用户测试迁移脚本。验证数据完整性， 并确保用户可以使用旧系统和新系统登录。

中文 - 中文提示词

中文 - 中文提示词
使用功能标志实现渐进式推出逻辑，逐步将用户从 Firebase 迁移到 Auth0。

中文 - 中文提示词
在每个阶段后运行完整的测试套件，包括单元测试、集成测试和端到端测试。

中文 - 中文提示词
设置自动化测试，在每个阶段边界验证认证迁移功能。

⭐ 最佳实践

✅ 从只读更改开始 (Start with Read-Only Changes) - 在开始修改之前，从分析和准备开始阶段
✅ 保持向后兼容性 (Maintain Backward Compatibility) - 在构建新系统时保持旧系统工作
✅ 使用功能切换 (Use Feature Toggles) - 允许逐步推出，并在需要时快速回滚
✅ 记录学习成果 (Document Learnings) - 根据实现过程中的发现更新计划
✅ 测试边界条件 (Test Boundary Conditions) - 专注于新旧系统之间接口的测试
✅ 为回滚做计划 (Plan for Rollback) - 如果发现关键问题，每个阶段都应该是可逆的
✅ 沟通进度 (Communicate Progress) - 定期向利益相关者提供进度报告更新

🚨 恢复策略

⚠️ 如果某个阶段遇到重大问题

  1. 立即回滚 (Rollback Immediately) - 使用git恢复到最后一个稳定状态
  2. 问题分析 (Problem Analysis) - 记录出错的原因和原因
  3. 计划调整 (Plan Adjustment) - 根据学习情况更新剩余阶段
  4. 利益相关者沟通 (Stakeholder Communication) - 更新时间表和期望

系统方法确保大型功能可靠地交付，同时在整个过程中保持代码质量和系统稳定性。
