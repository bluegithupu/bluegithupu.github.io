☕ Java 线程池入门 (Executor 框架快速上手)

理解线程池的核心概念、参数与最佳实践，帮助你写出更高效、更稳定的并发程序。

1. 为什么需要线程池？

频繁创建与销毁线程的开销巨大，线程数量不受控制还可能耗尽系统资源。线程池通过重用已创建的线程、统一调度任务、限制并发度，为程序提供了更优的性能和可控性。

使用线程池的好处：
  • 减少频繁创建线程带来的资源消耗。
  • 通过队列和拒绝策略控制任务并发量。
  • 统一配置线程名称、优先级、守护属性等。
  • 为监控与故障排查提供统一入口。

2. Executor 框架概览

JDK 5 之后引入了 java.util.concurrent 包，Executor、ExecutorService 和 ThreadPoolExecutor 构成了线程池的核心。

核心接口 / 类 作用
Executor 最基础的任务执行接口，定义了 execute(Runnable) 方法。
ExecutorService 扩展了任务提交、返回结果、关闭线程池等能力（如 submit、shutdown）。
ThreadPoolExecutor 线程池的核心实现类，提供丰富的构造参数与行为定制。
Executors 线程池工厂工具类，提供常见线程池的快捷创建方法。

3. 常见线程池类型

Executors 提供了一系列静态方法快速创建线程池，适合作为入门示例：

  • Executors.newFixedThreadPool(n)：固定线程数，适合控制并发数量的 CPU 密集型任务。
  • Executors.newCachedThreadPool()：按需创建，适合大量短生命周期、轻量级任务。
  • Executors.newSingleThreadExecutor()：单线程顺序执行，常用于串行任务或日志处理。
  • Executors.newScheduledThreadPool(n)：支持延迟与周期性任务调度。
生产环境建议： 虽然 Executors 快捷方法使用方便，但它们通常使用无界队列或最大线程数，可能带来 OOM 风险。建议直接使用 ThreadPoolExecutor 并明确配置参数。

4. ThreadPoolExecutor 关键参数

ThreadPoolExecutor 的常用构造方法如下：

public ThreadPoolExecutor(int corePoolSize,
                          int maximumPoolSize,
                          long keepAliveTime,
                          TimeUnit unit,
                          BlockingQueue<Runnable> workQueue,
                          ThreadFactory threadFactory,
                          RejectedExecutionHandler handler)

参数说明

  • corePoolSize：核心线程数，线程池会尽量保持这些线程存活。
  • maximumPoolSize：最大线程数，当队列满时会创建新线程直到达到上限。
  • keepAliveTime + unit：非核心线程的空闲存活时间。
  • workQueue：任务队列，用于缓存待执行的任务。
  • threadFactory：定义线程创建方式（命名、优先级、是否守护线程等）。
  • handler：拒绝策略，在任务无法被执行时触发。

5. 线程池的执行流程

  1. 线程池未达到 corePoolSize 时直接创建新线程处理任务。
  2. 达到核心线程数后，新任务会进入阻塞队列等待。
  3. 队列满且线程数未达到 maximumPoolSize 时，会继续创建线程。
  4. 若超过 maximumPoolSize 且队列也满，则触发拒绝策略。

6. 常见拒绝策略

策略 行为 适用场景
AbortPolicy 抛出 RejectedExecutionException。 默认策略，适合不允许丢任务的场景，配合调用方异常处理。
CallerRunsPolicy 由提交任务的线程直接执行任务。 节流效果，常用于削峰，避免过载。
DiscardPolicy 静默丢弃任务。 允许少量任务丢失的场景。
DiscardOldestPolicy 丢弃队列头部最旧的任务，然后尝试执行新任务。 适用于对最新任务实时性要求更高的业务。

7. 创建一个自定义线程池

AtomicInteger threadNumber = new AtomicInteger(1);
ThreadFactory threadFactory = runnable -> {
    Thread thread = new Thread(runnable);
    thread.setName("worker-" + threadNumber.getAndIncrement());
    thread.setDaemon(false);
    return thread;
};

ThreadPoolExecutor executor = new ThreadPoolExecutor(
        4,                       // 核心线程数
        8,                       // 最大线程数
        60L, TimeUnit.SECONDS,   // 空闲线程存活时间
        new ArrayBlockingQueue<>(100),  // 有界队列
        threadFactory,
        new ThreadPoolExecutor.CallerRunsPolicy()  // 拒绝策略
);

通过自定义 ThreadFactory，可以统一线程命名与属性配置，方便定位日志或执行监控。示例中需引入 java.util.concurrent.* 与 java.util.concurrent.atomic.AtomicInteger。

8. 提交任务与关闭线程池

ExecutorService pool = Executors.newFixedThreadPool(4);

for (int i = 0; i < 10; i++) {
    final int taskId = i;
    pool.submit(() -> {
        System.out.println(Thread.currentThread().getName() + " 执行任务 " + taskId);
        try {
            Thread.sleep(1000L);
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
        }
    });
}

pool.shutdown();
if (!pool.awaitTermination(30, TimeUnit.SECONDS)) {
    pool.shutdownNow();
}

务必在业务结束后调用 shutdown() 或 shutdownNow()，否则 JVM 可能因线程未退出而无法停止。

9. 监控与调优建议

  • 通过 ThreadPoolExecutor#getActiveCount()、getQueue().size() 等方法实时观察运行状态。
  • 在指标系统中采集任务耗时、队列长度、拒绝次数等指标。
  • 根据任务性质（CPU 密集 / IO 密集）设置合理的核心线程数。
  • 结合实际压测结果动态调整线程池参数，避免盲目套用固定配置。
